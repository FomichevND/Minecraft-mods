# Декор Короля Обезьян — 1.12.0

Fabric 1.20.1 / Java 17 / прежний Fabric API. Новые библиотеки не добавлены. Все восемь предметов находятся во вкладке **«Двор Короля Обезьян»**, имеют собственные модели, рецепты, переводы RU/EN и составные формы коллизии/выбора.

| ID в namespace `zoldrax` | Размер Ш×Г×В | Возможности |
| --- | --- | --- |
| `monkey_king_food_shelf` | 3×1×2 | 6 продуктов по одному; фиксированные точки непосредственно на полке. |
| `monkey_king_preparation_table` | 3×1×2 | 4 продукта по одному; постоянные доска и держатель инструментов. |
| `monkey_king_supply_basket` | 1×1×1 | Настоящий контейнер на 9 слотов, стаки до 64; до 12 представительных моделей реального содержимого. |
| `monkey_king_drying_rack` | 3×1×2 | 5 продуктов, подвешенных к крючкам. Без превращения сырой еды в приготовленную. |
| `monkey_king_courtyard_gong` | 3×1×3 | Удар по ПКМ, звук колокола с пониженной высотой/громкостью на радиус ~32 блока, раскачивание; задержка 16 тиков. |
| `monkey_king_festival_bench` | 3×1×2 | Два отдельных места для настоящих игроков; третий игрок не занимает уже занятое место. |
| `monkey_king_notice_board` | 3×1×3 | Три документа: бумага, пустая/заполненная карта, книги, свитки из совместимого тега. |
| `monkey_king_festival_drum` | 2×2×2 | Глубокий звук большого барабана, короткий импульс мембраны; задержка 3 тика для простого ритма. |

ПКМ едой кладёт **одну** единицу в свободное место. Shift+ПКМ пустой рукой забирает продукт; точка клика выбирает ближайшее место на полке/столе/сушилке. Пустая рука открывает корзину; её GUI позволяет выбрать любой слот. Доска открывает настоящую книгу выбранного документа; карты рисуются по их реальному MapState. Бумага не получает выдуманного текста. Скамья освобождается через Shift или повторное взаимодействие. Предметы при полном инвентаре возвращаются выпадением рядом с игроком.

Все транзакции выполняет сервер; блоки синхронизируют содержимое клиентам. Поворот распространяется на геометрию, коллизии, места и еду. Нельзя заменить занятый слот вставкой. Разрушение любой составной части удаляет весь объект и выдаёт ровно один блок с его содержимым. Поршни составную мебель не перемещают. Все состояния/инвентари сохраняются штатным NBT; сидящие игроки используют невидимый транспорт, отдельные entities для еды не создаются.

## Объёмная еда

`MonkeyFoodCatalogTests` выгрузил список непосредственно из Registries.ITEM Minecraft 1.20.1: **40 ванильных съедобных предметов**. [Полный список](monkey-decor/vanilla-food-catalog.json). У каждого отдельная редактируемая voxel-модель; также созданы модели торта (его предмет не помечен `isFood`) и золотого банана мода. Всего **42 модели еды**.

Формы: яблоки с черенком/листьями; золотые варианты; сужающаяся морковь с ботвой; корнеплоды; буханка с надрезами; объёмные печенье/пирог/торт; долька арбуза с кожурой/семенами; отдельные виды рыб с хвостом/плавником/глазами; разные силуэты мяса; ягоды; миски с жидкостью/ингредиентами; бутылочка мёда; слоёная ламинария; глаз паука и редкие продукты. Текстуры основаны на узнаваемой ванильной цветовой гамме, нарисованы заново, без копирования файлов игры.

`FoodDisplayModelRegistry` — клиентский реестр с кешем мешей и перезагрузкой ресурсов. Другие моды могут зарегистрировать модель через `register(Item, Identifier model, Identifier texture)` или добавить запись в `assets/zoldrax/food_models.json`. Если подходящая еда другого мода не имеет модели, используется обычный ItemRenderer: предмет не исчезает. Для всех 40 ванильных съедобных предметов резервный плоский рендер не используется.

`FoodDisplaySlots.Slot` содержит локальные координаты, угол, максимальный размер и признак подвешивания. Меш нормируется по фактическим границам, стоит нижней гранью на поверхности или висит ниже крючка. Корзина показывает выборку только из имеющихся стаков, повторяя продукт не больше его реального количества; число видимых моделей ограничено 12. По мере добавления продуктов выборка заполняет несколько слоёв. Она не изображает все 576 возможных единиц поштучно.

## Модели, текстуры и визуальное соответствие

- Мебель: `design/blockbench/monkey_king_decor/`, 8 `.bbmodel`, текстуры 64×64.
- Еда: `design/blockbench/food_models/`, 42 `.bbmodel`, текстуры 32×32.
- Идентичные runtime-модели: `assets/zoldrax/models/blockbench/decor/` и `food/`; PNG: `textures/block/zoldrax/`.
- Исходные генераторы: `tools/generate_monkey_decor.py`, `generate_food_models.py`, `generate_monkey_decor_data.py`.
- Проверка: `tools/validate_monkey_decor.py`; программные виды геометрии: `tools/render_monkey_decor.py`.

По референсам перенесены деревянные стойки и навес полки, рабочая доска/инструменты стола, открытое плетение корзины, бамбуковая рама и пять крючков сушилки, круглый ступенчатый гонг с объёмным бананом и молотком, широкое красное сиденье с подлокотниками, деревянная доска с навесом/вымпелом, круглая мембрана барабана на подставке. Все выступающие детали — геометрия. Единую палитру составляют джунглевое дерево, бамбук, верёвка, красная ткань и жёлтая отделка; демонические детали Золдракса не используются.

Изображения перспективные; невидимые обратные поверхности реконструированы. Пропорции адаптированы к заданным размерам Minecraft. Результат не объявляется точной попиксельной копией художественных иллюстраций.

## Поселения и интерфейсы для NPC

Обновлены отдельные шаблоны больших поселений: у святилищ появились полка и скамья, на праздничной площадке — гонг и барабан, у зала глашатая — доска, в кухне — стол, в складе — корзины, у зала добытчиков — сушилка. Это настоящие зарегистрированные блоки с корневыми BlockEntity/инвентарями и техническими частями. Опоры локальны; общая квадратная платформа не возвращается. Новые предметы появляются **в новых чанках**, старые локации автоматически не перестраиваются.

Публичные методы `insertDisplay`, `takeDisplay`, `strike`, `sitOnBench`, стандартный Inventory и описания FoodDisplaySlots доступны для будущего поведения NPC. Новые задачи ИИ не добавлялись. Подготовка/сушка здесь означают хранение и демонстрацию: отдельный экран переработки пищи и дополнительные рецепты приготовления не добавлены.

Правило испытаний сохранено: они работают **только у алтарей, установленных и построенных игроком**. Декор не запускает задания. Предыдущий набор Золдракса и остальные механики мода сохранены.
