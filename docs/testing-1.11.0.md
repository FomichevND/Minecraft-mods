# Проверки 1.11.0

Minecraft 1.20.1, Java 17.0.13, Gradle 8.7, Fabric Loom 1.6.12; Fabric API 0.92.2+1.20.1. Новых зависимостей мода нет.

**75 серверных GameTest-сценариев прошли без ошибок**: 60 прежних сценариев и 15 новых для декора. XML: [gametest-1.11.0.xml](decor/gametest-1.11.0.xml). После финальных правок дополнительно прошли все [15 сценариев декора](decor/gametest-decor-final.xml). Полная регистрация содержит 76 сценариев: длительный неизменённый тест частоты больших поселений, уже измеренный в 1.9.1, в этом прогоне исключён.

```sh
./gradlew -PskipFrequency runGametest
./gradlew build
python3 tools/validate_decor.py
python3 tools/validate_models.py
```

Без `-PskipFrequency` запускается также прежний тест частоты генерации. Требуются Java 17 и доступные Gradle-зависимости. Генераторы/программные превью используют Python с Pillow/numpy; это инструменты разработки, не зависимости JAR.

## Новые серверные проверки

`DecorTests` использует настоящий BlockItem.place, серверные BlockEntity, реальную структуру-площадку и штатные контейнерные обработчики.

1. Все 8 объектов устанавливаются в 4 горизонтальных направлениях, занимают правильные ячейки, удаляются вместе со скрытыми частями и единственным BlockEntity.
2. Препятствие по высоте отклоняет установку без расхода предмета.
3. Источники света переключают все ячейки; уровни 15/12/14 и сериализация состояния проверены.
4. Подвес 1/2 блока не проходит через препятствие и не оставляет частей после сокращения.
5. Стойка принимает 3 оружия, отклоняет неподходящие предметы/заполненные слоты, сохраняет прочность и имя, возвращает предмет без дублирования.
6. У сундука 27 сохраняемых слотов; два ServerPlayer одновременно открывают стандартное меню, закрытие одного не закрывает второго.
7. Настоящие тикающие воронки вставляют предметы через верхнюю часть сундука и извлекают снизу; суммарное количество не меняется.
8. Пюпитр открывает настоящий LecternScreenHandler, сохраняет номер страницы и возвращает книгу, сохраняя предмет в занятой руке.
9. Подставка расходует ровно один предмет, не заменяет занятый слот, сохраняет/возвращает подношение.
10. Трон принимает одного игрока, отклоняет второго, позволяет повторно встать/сесть; разрушение верхней части высаживает игрока.
11. Разрушение части стойки выдаёт ровно один блок и каждое хранимое оружие ровно один раз.
12. Удаление потолка снимает фонарь целиком.
13. При полном инвентаре возврат подношения выбрасывает ровно один предмет. Проверяется настоящий ServerPlayer: простой GameTest mock PlayerEntity не добавляет создаваемый dropItem в серверный мир, поэтому для этой проверки он не подходит.
14. Расширенные тестовым datapack теги принимают дополнительное оружие/бумажный свиток. Эти тестовые теги не попадают в выпуск.
15. Все 8 рецептов зарегистрированы и выдают соответствующие предметы.

Прежние проверки трёх божеств, наград/рейдов/обмена/доставки, построек, жителей и происхождения алтарей также прошли. Природные алтари не получают испытаний; игроковые сохраняют прежнюю механику.

## Ресурсы и визуальная проверка

`validate_decor.py` проверяет 8 разных мешей, 777 кубоидов, конечные размеры/повороты, уникальные UUID, полное дерево групп, UV внутри 256×256, встроенные PNG и их точное совпадение с runtime-текстурами, идентичность моделей в design/runtime, переводы, рецепты и отсутствие добычи технических частей. Старый валидатор моделей также прошёл.

Настоящий клиент Minecraft запущен на виртуальном Xvfb-экране с программным OpenGL Mesa. `DecorClientPreview` находится только в gametest source set и не включается в выпускаемый JAR. Он подготавливает тестовую площадку, выставляет реальные оружие/книгу/подношение, снимает каждый объект спереди/сбоку/сзади/сверху, открывает сундук и книгу, сажает игрока и показывает творческую вкладку. Отдельные SEA_LANTERN в основании/потолке задают обычное блочное освещение площадки; эффект ночного зрения в итоговом прогоне выключен.

Игровые снимки: [галерея из 42 снимков](decor/client/README.md) в `docs/decor/client/`; программные ортографические исходные виды обозначены `*-source.png`. Различия скрытых сторон и адаптация перспективных концептов описаны в [отчёте](decor-1.11.0.md). Дополнительно resource pack загрузил все восемь мешей без нестандартных полей `zoldrax_group`/`zoldrax_emissive` и без нулевых rotation: группы восстановлены из стандартного outliner, свечение — из UV материалов. Это проверка устойчивости к нормализации JSON, а не заявление о запуске самого редактора Blockbench.

После просмотра исправлены поворот оружия, перекрывающий светящийся стержень корпус, совпадающие поверхности, боковые знамёна/цепи сундука и чрезмерно белый additive-огонь.

Для повторения клиентского обзора сначала создайте тестовый мир и скопируйте его в `build/decor-client/saves/DecorReview`, затем запустите `./gradlew runDecorPreview`. Эта команда меняет только специальный мир обзора; не используйте имя DecorReview для своего игрового мира.

Посадка/контейнеры испытаны с двумя серверными игроками в GameTest, рендер и экраны — в интегрированном клиенте. Подключение двух отдельных графических клиентов и совместимость со сторонними модами отдельно не проверялись. Есть прежние предупреждения shader `zoldrax:monument` о неиспользуемом Sampler2 и недоступной внешней авторизации development-профиля; критических исключений рендера нового декора не обнаружено. У виртуальной среды нет аудиоустройства: OpenAL отключил воспроизведение, поэтому звуки реализованы и зарегистрированы, но на слух здесь не проверялись.
